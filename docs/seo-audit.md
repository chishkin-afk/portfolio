# SEO-аудит CHISHKIN — 17 октября 2026

Проверены опубликованный `https://echishkin.ru/`, ответы HTTP, robots.txt,
sitemap.xml и исходный HTML. Отдельно проверен код проекта. Данные из закрытых
отчётов Google Search Console и Яндекс Вебмастера недоступны; наличие сайта в
индексе, поисковый трафик и позиции по запросам этим аудитом не подтверждены.

## Исходное состояние опубликованного сайта

| Проверка | Результат |
| --- | --- |
| HTTPS, главная | HTTP 200, HTML доступен обычному клиенту и с User-Agent Googlebot |
| HTTP → HTTPS | Постоянный редирект 308 |
| www → основной домен | Редирект 307 на `https://echishkin.ru/`; на уровне Vercel желательно сделать постоянным |
| Несуществующая страница | HTTP 404 |
| Запреты индексации главной | В HTML `index, follow`; заголовок `X-Robots-Tag: noindex` не обнаружен |
| robots.txt | Разрешает обход и содержит адрес sitemap |
| sitemap.xml | Корректный XML, одна главная страница |
| Canonical | Указывает на основной HTTPS-домен |
| Контент без JS | Основное описание, проект и первый вариант сроков присутствуют в исходном HTML |
| Социальные метаданные | Open Graph с PNG 1200×630 и Twitter Card |
| JSON-LD | Person, WebSite, WebPage, Service |
| Подтверждение Google | В HTML content содержит DNS-префикс `google-site-verification=`; для HTML-способа нужен только токен |

Основа подходит для обхода и технически не запрещает индексацию. Главные ограничения
для продвижения — краткое содержание, одна страница для нескольких разных услуг,
H1 с брендом вместо описания предложения и отсутствие подробных кейсов с
подтверждёнными результатами. Количество meta keywords не устраняет эти ограничения.

Отсутствие результата в публичном поиске с `site:` не доказывает отсутствие
индексации: окончательную проверку нужно выполнить инструментом проверки URL в Search Console.
Имитация User-Agent Googlebot проверяет HTTP-ответ, но не заменяет запрос настоящего робота Google.

## Изменения в проекте

- Главная направлена на запрос «разработка сайтов под ключ». Видимый H1 описывает
  услугу. По пожеланию владельца представление «Я Егор, веб-разработчик…» оставлено
  только на главной; на страницах услуг, в метаданных и рекламных формулировках имя не используется.
- Три отдельные страницы раскрывают разные задачи: лендинг, сайт компании и
  веб-приложение. После сокращения на страницах оставлены краткое предложение,
  состав работ, ориентиры сроков и два свёрнутых ответа. Цены, отзывы,
  клиентские результаты и география не выдуманы.
- Для каждой страницы задаются собственные title, description, canonical и og:url.
  Canonical главной больше не наследуется всеми будущими страницами.
- Добавлены ссылки с главной на услуги, между услугами и обратно к портфолио.
  Sitemap включает все четыре страницы.
- Разметка сайта едина; страницы услуг содержат Service и BreadcrumbList.
  FAQ виден пользователю, но не сопровождается обещанием расширенного сниппета Google.
- Весь текст генерируется статически, раскрытие вопросов не требует загрузки JS.
- Локальный Manrope подключён через next/font/local: предзагрузка и метрики
  запасного шрифта уменьшают риск сдвигов при смене шрифта.
- Исправлена обработка случайно вставленной TXT-строки в переменную HTML-подтверждения Google.

## Что проверить после публикации

1. В Search Console открыть проверку URL главной и каждой страницы услуги.
   Выполнить проверку опубликованного URL: Google должен получать HTTP 200,
   корректный canonical и полный текст. При необходимости запросить индексирование.
2. Повторно передать sitemap.xml. Следить за выбранным Google canonical и причинами
   исключения страниц в отчёте об индексировании.
3. В настройках домена Vercel сделать редирект с www постоянным — 301 или 308.
4. Проверить мобильную версию и Core Web Vitals в PageSpeed Insights / Search Console.
   Числовая оценка скорости и полевые показатели данным аудитом не измерялись.
5. Отслеживать запросы с фамилией отдельно от общих коммерческих запросов.
   Для принятия решений использовать реальные показы, клики и обращения, а не
   только ручную проверку позиций, зависящую от региона и персонализации.
6. Дополнять портфолио реальными проектами и содержательными кейсами. Добавить ссылки
   на сайт в собственные профессиональные профили. Если есть основной регион работы,
   указать его и условия сотрудничества после подтверждения владельцем.

## Проверка подготовленных изменений

- `npm run build` и `npm run typecheck` проходят.
- `npm run verify:seo` проверяет статический HTML всех четырёх страниц: уникальные
  метаданные, canonical, og:url, превью, локальный шрифт, ссылки и якоря, связность
  графа JSON-LD, sitemap и noindex на странице ошибки.
- Локальная production-версия отдаёт HTTP 200 для четырёх страниц, robots.txt,
  sitemap.xml и превью. Неизвестный URL, в том числе неизвестная услуга, отдаёт 404
  с noindex.
- В браузере проверены переход с главной на услугу и раскрытие ответа в FAQ.
  Макет страницы услуги просмотрен на ширине 1280 px, корпоративный сайт — также
  в iframe с viewport 390 px. Это проверка адаптивной вёрстки, а не замер Core Web Vitals.
- Изменения подготовлены локально; опубликованная версия изменится после деплоя.

## Практические пределы

Публикация кода и запрос переобхода не гарантируют попадания в индекс или первую
строку. По широкому запросу «разработка сайтов под ключ» сайт конкурирует с другими
исполнителями. Техническая доступность, содержание, репутация и реальные подтверждения
работ должны развиваться вместе. Брендовые запросы и конкретные услуги следует
оценивать отдельно; никаких сроков достижения топа этот аудит не устанавливает.
